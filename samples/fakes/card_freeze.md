# Временная заморозка карты в приложении

Комплект из двух документов: функциональные требования и REST API. Учебный пример, все данные вымышлены.

## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Временная заморозка и разморозка карты клиентом |
| **Продукт** | Мобильный банк, учебный кейс |
| **Бизнес-процесс** | Управление картой |
| **Business owner / Product owner / Аналитик** | Учебные роли карточного бизнеса, владельца мобильного банка и аналитика команды |
| **Тип работы** | Новый функционал |
| **Влияние на ИС** | Мобильный банк, карточный процессинг, сервис уведомлений |

### Цели
Клиент сам временно ограничивает операции по карте, если потерял её, и снимает ограничение, когда карта нашлась.

### Дизайн процесса UI
Карты → выбранная карта → «Заморозить». На замороженной карте видна плашка «Заморожена» и кнопка «Разморозить».

### Требования к изменениям

#### Функциональные требования
* **Ф-1.** Клиент замораживает карту кнопкой «Заморозить» на экране карты. Блокировка действует мгновенно.
* **Ф-2.** Замороженная карта отклоняет все операции.
* **Ф-3.** Регулярные платежи и подписки по замороженной карте продолжают проводиться.
* **Ф-4.** Клиент размораживает карту в приложении в любое время. Через 30 дней заморозки карта блокируется навсегда и перевыпускается.
* **Ф-5.** Заморозить карту можно не больше 5 раз в месяц. Уведомление о заморозке отправляется согласно Ф-6.

### Нефункциональные требования
Заморозка срабатывает за 2 секунды.

### Требования к данным
Хранить статус карты (активна или заморожена) и дату заморозки.

### Требования к интеграции
Статус карты передаётся в процессинг. Если процессинг недоступен, заморозка отображается клиенту как выполненная.

### Критерии приемки

| Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Карта заморожена | Покупка в магазине на 3 000 ₸ | Операция отклонена |
| Карта заморожена 10 дней | Нажать «Разморозить» | Карта активна |
| Карта заморожена | Списание подписки 2 990 ₸ | Операция отклонена |
| Шестая заморозка за месяц | Нажать «Заморозить» | Карта заморожена |

## Часть B. REST API

Дочерний документ части A: «Временная заморозка карты, REST API».

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Заморозка карты методом DELETE, разморозка методом POST |
| **Authorization** | Bearer, сессия клиента |
| **Controller** | CardFreezeController |
| **Request URL** | Dev: `/cards/{cardId}/freeze` |

### Параметры запроса

#### Path-параметры

| Parameter | Format | Mandatory | Description |
| :--- | :--- | :--- | :--- |
| `cardId` | string | Да | Номер карты (16 цифр) |

### Статусы

**200.** Статус карты изменён.
**409.** Лимит заморозок за месяц исчерпан.
**401.** Ответ в случае, если запрос выполнен без необходимой авторизации.
**403.** Ответ в случае, если на указанный ресурс доступ запрещен.
**500.** Ответ в случае, если произошла внутренняя ошибка сервера.
