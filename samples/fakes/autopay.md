## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |

### Цели
Клиент никогда не остаётся без связи: банк пополняет номер сразу, как только баланс станет низким.

### Архитектура решения
Мобильное приложение → сервис автоплатежей → шлюз операторов → оператор связи.

### Дизайн процесса UI
Платежи → Мобильная связь → Автопополнение. На экране поле номера, поля «Порог, ₸» и «Сумма пополнения, ₸», выбор карты и кнопка «Подключить».

### Требования к изменениям

#### BPMN схема процесса
Запрос баланса → сравнение с порогом → списание с карты → пополнение номера → push клиенту.

#### Функциональные требования
* **Ф-1.** Клиент подключает автопополнение для номера оператора Kcell, Beeline или Altel и задаёт порог баланса от 100 до 5 000 ₸ и сумму пополнения от 500 до 20 000 ₸.
* **Ф-2.** Когда баланс номера опускается ниже порога, система списывает сумму пополнения с выбранной карты и пополняет номер. Пополнений не больше трёх в сутки.
* **Ф-3.** Если на карте недостаточно средств, система повторяет списание.
* **Ф-4.** Баланс номера запрашивается у оператора каждые 15 минут.
* **Ф-5.** Клиент может приостановить автопополнение. На время приостановки списания не выполняются.

### Sequence Diagram
Сервис автоплатежей → шлюз: запрос баланса. Шлюз → сервис автоплатежей: баланс. Сервис автоплатежей → процессинг: списание. Сервис автоплатежей → шлюз: пополнение номера.

### Нефункциональные требования
Интерфейс должен быть удобным и интуитивно понятным. Пополнение проходит быстро.

### Требования к данным
Хранить номер телефона, оператора, порог в тенге, сумму пополнения в тиынах, полный номер карты для повторных списаний и историю пополнений.

### Требования к интеграции
Взаимодействие с операторами реализовать через брокер Kafka, топик topup-requests. При таймауте оператора пополнение повторяется.

### Требования к тестированию

#### Тестирование требований
заполняются тестировщиками

### Критерии приемки

| Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Порог 500 ₸, баланс 520 ₸ | Звонок, баланс стал 480 ₸ | Номер пополнен на сумму пополнения в течение 15 минут |

## Часть B. REST API

Дочерний документ части A: «Автопополнение баланса мобильного телефона, REST API».

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Создание настройки автопополнения |
| **REST type** | POST |
| **Authorization** | Bearer, сессия клиента |
| **Controller** | AutopayController |
| **Request URL** | Dev: `/autopay/settings` . Prod: не указан |
| **CURL** | `curl -X POST "$BASE/autopay/settings" -H "Authorization: Bearer $TOKEN" -d '{"phone":"7015550000","threshold":500,"amount":2000,"cardId":"demo-7"}'` |
| **Author** | Школа тестирования |

### Логика работы метода
1. Проверить пользовательскую сессию.
2. Проверить принадлежность карты клиенту.
3. Проверить порог и сумму пополнения.
4. Создать настройку и вернуть её идентификатор.

### Особые правила
1. Номер телефона передаётся в любом формате.
2. Повторный запрос для того же номера создаёт ещё одну настройку.

### Параметры запроса

#### Request body

| Parameter | Format | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `phone` | string | Да | Номер клиента | Номер телефона | `phone` |
| `threshold` | integer | Да | от 100 до 5 000 | Порог в тенге | `threshold_kzt` |
| `amount` | integer | Да | от 500 до 20 000 | Сумма пополнения | `amount_tiyn` |
| `cardId` | string | Да | Карта клиента | Идентификатор карты | `card_id` |

### Ответ

| Parameter | Format | Logic | Description |
| :--- | :--- | :--- | :--- |
| `id` | string | При успехе | Идентификатор настройки |
| `message` | string | При ошибке | Описание ошибки |

### Статусы

**200. Created.** Настройка создана.
**400.** Параметры запроса заполнены неверно.
**401.** Ответ в случае, если запрос выполнен без необходимой авторизации.
**403.** Ответ в случае, если на указанный ресурс доступ запрещен.
**500.** Ответ в случае, если произошла внутренняя ошибка сервера.
